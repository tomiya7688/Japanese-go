# Japanese-go 基本文法 v0.1 仮案

状態: **検討用の初案。確定仕様ではなく、実装済み機能の一覧でもありません。**

初案作成日: 2026-10-19（日本時間）

## 1. 目的と準拠範囲

日本語の構文語でGoのプログラムを書けるようにします。初案では**語順と意味を変えず、Goの予約語に日本語表記を追加する**方式を採ります。

意味論の仮の基準はGo 1.23です。これは最新バージョンの宣言ではありません。将来の変換器は対象Goバージョンを明示し、別バージョンの新機能を自動的に保証しません。

ソースの拡張子は `.jgo`、文字コードはUTF-8を想定します。型検査・スコープ・評価順・メモリモデル・実行時動作は対応するGoに委ねます。新しい例外機構、クラス、VM、日本語専用ランタイムは追加しません。

## 2. 変換による定義

日本語ソース `S` に対し、次の処理で通常のGoソース `T(S)` を得るものとします。

1. Goの字句境界に従い、文字列・runeリテラル・コメントを区別する。
2. 識別子全体が§3の日本語表記に一致するときだけ、対応するGo予約語へ置き換える。
3. それ以外のソースの内容と改行を保つ。文字列・runeリテラル・コメントの内部は置き換えない。
4. 変換後のトークン種別に従ってGoの自動セミコロン挿入と構文解析を行う。

`T(S)` が基準Goの文法・型・その他の制約に適合するとき、そのプログラムの意味をJGoの意味とします。単一ファイルだけでは決まらない名前や型の妥当性は、所属パッケージと依存関係を含めて検査します。

これは仕様上の定義であって、実装言語や内部構造の指定ではありません。25語を置換できても、診断位置やビルド統合まで完成したとは扱いません。

### 2.1 字句境界と予約語

日本語の構文語も予約語です。変数名・関数名・フィールド名・ラベル・パッケージ名などに、その語自体を使うことはできません。セレクタの後などの文脈で特別扱いする案は採りません。予約語を識別子として使うエスケープ構文も初案にはありません。

```jgo
返す 値       // return 値
返す(値)      // return(値): 同じくreturn文。関数呼び出しではない
返す値 := 1   // 「返す値」という単一の識別子。置換しない
もし 条件 {   // if 条件 {
```

`もし条件` は一つの識別子であり、`もし` と `条件` には分解しません。構文語と識別子が続く箇所はスペース等で区切ります。`それ以外 もし` は2個の予約語であり、`それ以外もし` や `それ以外でもし` を別名として認識しません。

空白・記号はGoに従います。全角スペースをGoの空白として追加したり、全角の括弧や演算子を半角へ自動変換したりしません。Unicode正規化も行いません。

JPyの `返す(x)` を識別子の呼び出しとして扱う規則は持ち込みません。語の前後のスペースで同じ予約語の意味が変わらないようにする案です。

### 2.2 文字列・コメント

```jgo
文章 := "もし 関数 返す"   // この文字列の中は置換しない
生文字列 := `関数の終わりに 行け`    // raw文字列の中も置換しない
文字 := '型'              // runeリテラルの中も置換しない
// 関数・もし・返す: コメントの中も置換しない
/* 複数行のコメントも保存する */
```

構造体タグも文字列なので保存します。`//go:build`、`//go:embed` などのGo用ディレクティブは日本語化しません。ただし、その保存だけで複数ファイル・埋め込み資産を含むビルドの互換性が保証されるわけではありません。

### 2.3 改行とセミコロン

自動セミコロン挿入は、**日本語の予約語をGoの予約語に対応付けた後**に適用します。`go/scanner` などで日本語の予約語を通常の識別子として読んだ時点の、挿入済みセミコロンをそのまま採用してはいけません。

例えば、次は `func` の直後の改行と同様に扱う案です。

```jgo
関数
main() {
}
```

`返す` の行末では `return` と同じくセミコロンが挿入されます。`返す` と戻り値を不用意に別の行へ分けません。通常の例は `もし 条件 {`、`} それ以外 {` のように、Goの改行規則に合う書式を用います。

### 2.4 英語との混在

```jgo
func 判定(値 int) bool {
    もし 値 > 0 {
        return true
    }
    返す false
}
```

元のGoの予約語は維持します。ただし追加の日本語予約語と識別子が衝突するGoコードは、そのままJGoとしては読めません。Go全体の厳密な上位集合とはしません。

## 4. 基本文法

以下は、特記しない限りコードの断片です。未定義の変数や呼び出し先は周囲のコードで定義します。単独のプログラム例は `examples/` に置きます。

### 4.1 パッケージと読み込み

```jgo
パッケージ main

読み込む "fmt"
```

別名はGoの語順を保ち、パスの前に置きます。`として` は追加しません。

```jgo
読み込む 表示 "fmt"
読み込む (
    "os"
    数学 "math"
)
```

`読み込む _ "パス"`、`読み込む . "パス"` も、それぞれGoのblank import、dot importと同じ規則です。インポートパスの文字列は変更しません。

### 4.2 変数・定数・代入

```jgo
変数 点数 int = 80
変数 名前 = "太郎"
定数 合格点 = 60
変数 (
    回数 int
    有効 bool = true
)
```

関数内の `値 := 式`、複数代入、`+=`、`++`、`_` もGoのままです。`:=` をパッケージ直下で使えるようにはしません。未使用のローカル変数やimportなど、Goが拒否するコードをJGo独自に許可しません。

### 4.3 関数と戻り値

```jgo
関数 足す(左 int, 右 int) int {
    返す 左 + 右
}

関数 割る(左 int, 右 int) (int, error) {
    もし 右 == 0 {
        返す 0, fmt.Errorf("0では割れません")
    }
    返す 左 / 右, nil
}
```

`返す` 単独、名前付き戻り値、複数の戻り値、可変長引数 `...` はGoの規則を保ちます。上の `fmt` は利用側で読み込みます。

```jgo
二倍 := 関数(値 int) int { 返す 値 * 2 }
変数 計算 関数(int) int = 二倍
```

`関数` は宣言だけでなく関数型・関数リテラルでも `func` に対応します。`値 を返す` という後置構文は初案にはありません。

### 4.4 条件分岐

```jgo
もし 点数 >= 80 {
    fmt.Println("優秀")
} それ以外 もし 点数 >= 60 {
    fmt.Println("合格")
} それ以外 {
    fmt.Println("不合格")
}

もし エラー := 処理(); エラー != nil {
    返す エラー
}
```

初期化文付きifもGoと同じです。`ならば`、コロンによるブロック、インデントだけのブロックは追加しません。

### 4.5 繰り返しと列挙

```jgo
繰り返し i := 0; i < 5; i++ {
    fmt.Println(i)
}

繰り返し 条件 {
    処理()
}

繰り返し {
    もし 終了条件 {
        抜ける
    }
}

繰り返し 添字, 値 := 列挙 一覧 {
    fmt.Println(添字, 値)
}

繰り返し 値 := 列挙 受信箱 {
    fmt.Println(値)
}
```

`列挙` はGoの `range` です。配列・スライス・文字列・マップ・チャネル、Go 1.22で追加された整数、Go 1.23で追加された所定の関数形式を対象とする際も、対象ごとの値の個数と反復規則を変更しません。マップの順序を保証したり、文字列を文字番号で添字付けしたり、チャネルのクローズを自動化したりしません。

整数を使う `繰り返し i := 列挙 5 { ... }` は `0` から `4` までです。独自の開始値・終了値・増分の糖衣構文は追加しません。

`抜ける [ラベル]` はGoの `break` と同じく、ループのほか `switch` / `select` にも使うため、「繰り返しをやめる」という名前にはしない案です。`繰り返しを続ける [ラベル]` はGoの `continue` と同じで、ループの次の反復へ進みます。ここでの角括弧は任意要素を表す説明上の記号です。

### 4.6 値・型による分岐

```jgo
分岐 点数 {
場合 100:
    fmt.Println("満点")
場合 80, 90:
    fmt.Println("高得点")
既定:
    fmt.Println("確認しよう")
}

分岐 値 := 対象.(型) {
場合 int:
    fmt.Println(値 + 1)
場合 string:
    fmt.Println(値)
既定:
    fmt.Println("その他の型")
}
```

後半の `対象` はインターフェース型の値を想定します。`型` は型宣言だけでなく、型スイッチの `.(type)` にも対応します。式を省略したswitchや初期化文付きswitchもGoのままです。

各節は自動で次の節へ落ちません。`次の分岐へ` はGoの `fallthrough` に対応し、式switchの最後以外の節の最終非空文として使います。次の節の条件を再判定せずに進みます。型switchやselectでは使えません。

### 4.7 型・構造体・インターフェース

```jgo
型 利用者 構造体 {
    名前 string
    年齢 int
}

型 挨拶できる インターフェース {
    挨拶() string
}

関数 (人 利用者) 挨拶() string {
    返す "こんにちは、" + 人.名前
}

関数 (人 *利用者) 改名(名前 string) {
    人.名前 = 名前
}

型 整数の別名 = int
```

フィールドとメソッドの公開範囲は§5に従います。配列 `[3]int`、スライス `[]int`、ポインタ `*利用者`、アドレス演算 `&値`、型アサーション `値.(型名)` はGoのままです。

```jgo
点数表 := マップ[string]int{"太郎": 80}
変数 任意の値 インターフェース{} = 点数表
```

ジェネリクスも独自の意味を加えず、Goの型パラメータ・制約の記法を残します。

```jgo
関数 先頭[T any](値一覧 []T) T {
    返す 値一覧[0]
}
```

空のスライスならGoと同じくpanicになります。日本語化によって境界検査やエラー処理を追加するわけではありません。

### 4.8 goroutine・チャネル・select

```jgo
受信箱 := make(チャネル string)
行け 関数() {
    関数の終わりに close(受信箱)
    受信箱 <- "こんにちは"
}()

繰り返し メッセージ := 列挙 受信箱 {
    fmt.Println(メッセージ)
}
```

`行け` はGoの `go` に対応します。呼び出す関数と引数の評価は呼び出し元側で行い、呼び出しの実行を別のgoroutineで開始します。戻り値の受け取りや完了待ちは追加しません。「必ず別CPUで並列に動く」という意味でもありません。

`チャネル T`、`チャネル<- T`、`<-チャネル T` は、それぞれ双方向・送信専用・受信専用の型です。通信演算子 `<-`、`close`、バッファ長、クローズ済みチャネルの動作はGoのままです。

```jgo
選ぶ {
場合 値 := <-受信箱:
    fmt.Println(値)
場合 送信箱 <- "通知":
    fmt.Println("送信した")
既定:
    fmt.Println("今は通信できない")
}
```

ここでの受信箱・送信箱は適切な型で宣言されている前提です。通信可能な候補がなければ `既定` を選び、`既定` がなければ待機します。複数が通信可能ならGoの選択規則に従い、記述順の優先度は付けません。

### 4.9 deferとエラー処理

```jgo
関数 作業() {
    関数の終わりに fmt.Println("終了")
    fmt.Println("作業中")
}
```

`関数の終わりに` は `defer` です。この表記は空白を含まない単一の構文語として扱い、途中の `返す`（`return`）や関数の末尾に到達して戻る場合にも動作します。呼び出す関数値と引数を登録時に評価し、周囲の関数を抜ける際に登録の逆順で呼び出します。単なるブロックの終端、タイマー、goroutineの起動ではありません。panicによるスタック巻き戻しにもGoの規則が適用されますが、`os.Exit` などのプロセス強制終了を含む「あらゆる終了で必ず実行」を意味しません。

`関数の終わり`・`関数終わりに`・`関数終わり` は短縮形の検討候補ですが、**この仮案ではまだ採用しません**。`関数 の 終わり に` のように空白で区切った語列も認めません。

通常のエラー処理は `error` と複数戻り値を利用します。`panic` / `recover` はそのまま使い、`試す` / `例外処理` / `throw` / `try` / `catch` は追加しません。

### 4.10 goto

```jgo
飛ぶ 終了
終了:
    返す
```

Goの `goto` と同じです。移動先・スコープに関する制約を緩和しません。

## 5. 日本語の識別子と公開範囲

Goでは、日本語を識別子に使えても、漢字・かなで始まる名前は公開名にはなりません。公開には先頭文字がUnicode大文字であり、パッケージブロックでの宣言・フィールド名・メソッド名であるというGoの条件を満たす必要があります。

```jgo
関数 足す(左 int, 右 int) int { 返す 左 + 右 }       // 非公開
関数 Add(左 int, 右 int) int { 返す 左 + 右 }        // 公開
関数 Add足す(左 int, 右 int) int { 返す 左 + 右 }    // 公開
```

上の例はパッケージ直下の宣言です。初案では自動改名・大文字接頭辞の自動挿入・`公開` 修飾子を導入しません。構造体の `名前` フィールドや `挨拶` メソッドも非公開です。公開が必要な標準インターフェースのメソッドなどは `Read`、`Write`、`String` のように元の名前を使います。

日本語名のまま公開したい場合は、複数パッケージでの名前解決、既存Goからの参照、フィールドやメソッドの扱いまで含む独立した設計課題にします。

## 6. 実装範囲の案

最初は単一 `.jgo` を通常の `.go` に変換する機能に絞ります。字句・構文チェックだけでなく、生成物をGoでコンパイルする受け入れテストを用意します。

`gofmt` は変換後のGoソースに適用できます。JGo用フォーマッタ、診断の日本語化、元ファイルへの行・列の対応、Go Modules、複数ファイル、ビルドタグ、埋め込み資産、cgo、デバッガ連携は追加設計が必要です。現時点では完全なツール互換性を保証しません。

このリポジトリには、まだ変換器・CLI・継続的テストの実装を含めません。

## 7. 実装時に用意する受け入れテスト案

| 観点 | 確認すること |
|---|---|
| 予約語25組 | 各日本語トークンが対応するGo予約語へ変わる |
| 基本プログラム | examplesの3本を個別に変換・ビルド・実行できる |
| 非置換箇所 | 文字列・raw文字列・rune・コメント・構造体タグを保存する |
| 識別子 | `返す値` を変えず、`返す` 自体の識別子利用を許さない |
| 混在 | 英語・日本語を混ぜても同じ意味になる |
| 改行 | `関数` の後の改行、`返す` の行末、改行入りコメントをGo同様に扱う |
| 制御文 | breakの対象、continueの対象、ラベル、fallthroughの制約を変えない |
| 関数の形 | メソッド・無名関数・関数型・複数戻り値を扱える |
| 並行処理 | チャネルの方向、go、defer、select、クローズを扱える |
| 型 | 構造体・interface・map・型スイッチ・ジェネリクスを扱える |
| 公開範囲 | 別パッケージから日本語の非公開名へアクセスできない |
| 診断 | 不正な入力を黙って推測修正せず、失敗として報告する |

表は予定であり、テストが既に実装・完了しているという意味ではありません。

## 8. 未決事項

| 論点 | 今回の仮置き | 検討理由 |
|---|---|---|
| `go` の訳 | `行け` | 短く印象的だが、並行処理だと伝わるか。`並行` なども候補 |
| `defer` の訳 | `関数の終わりに` | 関数から戻るときの実行が伝わる表記。`関数の終わり`・`関数終わりに`・`関数終わり` を将来の短縮形として検討。旧案の `後で` は採用しない |
| `range` の訳 | `列挙` | 整数の範囲だけでなく、マップやチャネルにも使うため |
| `default` の訳 | `既定` | `それ以外` と別語にしてelseとの一対一対応を保つ |
| 予約語の扱い | 日本語の25語も常時予約 | 実装は単純だが、`型` などの一般的な識別子と衝突する |
| 公開名 | Goの規則のまま | 自動改名や独自修飾子は互換性への影響が大きい |
| 自然な日本語の語順 | 今回は追加しない | まず一対一の仕様を固めてから必要性を判断する |
| Goバージョン | 意味論の仮基準を1.23とする | 最新版対応とCIの正式対象は実装時に再検討する |

採用していない候補を変換器が推測して受け付けることはしません。文法を変更するときは、README・この文書・例・実装後のテストを同時に更新します。
